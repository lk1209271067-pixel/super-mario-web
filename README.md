# Super Mario Web —— 网页版超级玛丽

原生 JavaScript + HTML5 Canvas 实现的经典超级玛丽核心玩法复刻，**零依赖、零构建**，打开即玩。所有角色与场景图形均由代码程序化生成的像素数据绘制，不依赖任何外部版权素材。

## 快速开始

```bash
# 方式一：Python（任意机器自带）
python3 -m http.server 8000

# 方式二：Node
npx serve .
```

然后浏览器访问 `http://localhost:8000`。

> 注意：项目使用 ES Modules，必须通过 HTTP 服务访问，直接双击 `index.html`（file:// 协议）会被浏览器拦截。

## 操作

| 按键 | 功能 |
|------|------|
| ← → / A D | 左右移动 |
| 空格 / W / ↑ | 跳跃（长按跳更高，支持踩敌二段弹跳） |
| Shift | 加速跑（跑得越快跳得越高） |
| C | 第二关射击 / 第三关投掷石斧或火球 |
| R | 游戏结束 / 过关后重新开始 |

## 已实现的核心玩法

- **角色控制**：加速度 + 摩擦的惯性移动、急停转身、可变跳高（松键截断）、土狼时间（coyote time）、跳跃预输入缓冲（jump buffering）——手感向原作看齐
- **重力与碰撞**：固定步长积分，AABB vs 瓦片网格的分轴求解（先 X 后 Y），无穿透、可顶头
- **平台与地形**：地面分段、深坑（坠落死亡）、四根递增高度水管、双向楼梯、终点大楼梯与城堡
- **砖块与道具**：问号砖（顶出金币 / 蘑菇）、普通砖块（小马里奥顶起晃动、大马里奥顶碎成四块碎屑）、顶起的砖块可震死站在上面的敌人
- **金币系统**：场景旋转金币拾取、问号砖弹出金币、100 金币奖 1 命
- **敌人（板栗仔）**：接近屏幕才激活、左右巡逻撞墙转向、可走出平台边缘、踩踏压扁得分、侧面碰撞受伤（大马里奥变小 + 2 秒无敌闪烁，小马里奥死亡）
- **镜头**：带死区的跟随镜头，只向右滚动不可回卷，玩家无法退过镜头左缘
- **完整游戏循环**：300 秒倒计时、3 条命、死亡动画、过关滑旗杆 + 剩余时间折算分数、GAME OVER / LEVEL CLEAR 结算
- **像素风画面**：8-bit 调色板像素精灵（马里奥大小两种形态 × 站/走/跳三帧）、视差背景（远山 / 云 / 灌木）、`imageSmoothingEnabled = false` 保持锐利像素

## 第三关：冒险岛（Adventure Island）

第二关击败绿帽指挥官后走进开启的大门，即进入热带岛屿关卡。马里奥换上**野人装**（兽皮短裤 + 骨制项链 + 红色头带，仍沿用原有 16×14 像素网格与调色板），玩法按小霸王《冒险岛》核心机制重做：

- **体力槽**：持续衰减（满槽约 95 秒），吃水果按 1/2/3 格回复，喝牛奶回满；耗尽直接丢命
- **碰敌即丢命**：不再有血量缓冲，撞到蜗牛 / 蛇 / 青蛙 / 蝙蝠或掉进水里立刻损失一命；复活点为最近旗杆
- **滑板**：自动高速前进，只能靠按左减速，可挡一次伤害后损毁
- **妖精**：限时无敌，碰到敌人直接消灭
- **蛋与武器**：蛋需砸两下（第一下裂、第二下破），开出石斧 / 火球 / 牛奶 / 滑板 / 妖精；跑撞会把蛋顶飞，落水则道具丢失
- **石斧**：同时最多 2 把，直线飞行后下坠；**火球**：飞得更远、几乎不下坠
- **检查点与终点**：旗杆记录复活点；终点旗在巫医被击败后才开启
- **巫医 Boss**：三阶段（面具与投掷弹幕随血量升级），击败后结算剩余体力奖励并通关

`?stage=3` 可直接调试本关；`?god=1` 为无敌调试参数。

## 目录结构

```
super-mario-web/
├── index.html            # 入口页面（canvas + 操作说明）
├── package.json          # ESM 声明与启动脚本
├── README.md
├── css/
│   └── style.css         # 页面样式（像素化渲染、暗色游戏厅风格）
└── js/
    ├── main.js           # 启动引导 + 固定步长主循环（60Hz 物理 / 解耦渲染）
    ├── config.js         # 全部可调常量（尺寸、物理参数、计分规则）
    ├── input.js          # 键盘输入（含跳跃按下沿检测）
    ├── camera.js         # 死区跟随镜头（只向右滚动）
    ├── physics.js        # AABB vs 瓦片网格分轴碰撞求解
    ├── sprites.js        # 像素图数据 + 精灵构建 + 瓦片程序化绘制
    ├── level.js          # Level 类 + 函数式关卡建造器（关卡 1-1）
    ├── player.js         # 马里奥：移动手感/跳跃/受伤成长/动画状态机
    ├── enemies.js        # 板栗仔：巡逻/踩踏/震死
    ├── items.js          # 蘑菇 / 金币弹出特效 / 砖块碎屑粒子
    ├── contra.js         # 第二关：魂斗罗式 run-and-gun 关卡与 Boss
    ├── adventure.js      # 第三关：冒险岛（体力槽 / 蛋 / 石斧火球 / 巫医）
    ├── adventureData.js  # 第三关关卡数据（平台 / 水沟 / 敌人 / 蛋 / 水果）
    ├── transition.js     # 一→二关升空转场、二→三关进门转场
    └── game.js           # Game 主控：状态机、实体调度、分层渲染、HUD
```

## 核心模块划分说明

| 模块 | 职责 | 设计要点 |
|------|------|----------|
| `main.js` | 引导与主循环 | 固定步长累加器（60Hz），物理与渲染解耦，切后台不追帧 |
| `config.js` | 常量集中管理 | 调手感只改这一个文件 |
| `input.js` | 输入抽象 | 持续状态（left/right/jump/run）+ 边沿事件（jumpPressed）分离 |
| `physics.js` | 碰撞引擎 | 按位置索引瓦片，实体只检测周围几格；顶头时同排多砖取最近中心的一块（原作手感） |
| `level.js` | 关卡数据 | 函数式建图（`fill/pipe/stairs/coinRow/goomba/flag`），新关卡无需改引擎 |
| `sprites.js` | 图形资源 | 像素图字符串 → 离屏 canvas 精灵表；瓦片即时程序化绘制 |
| `player.js` | 玩家实体 | 手感三件套：coyote time + jump buffer + 可变跳高；大小形态切换 |
| `enemies.js` | 敌人类 | 状态机 walk/squash/flip；屏幕外休眠（原作激活机制） |
| `items.js` | 道具与粒子 | 蘑菇顶出动画（emerge 期间无碰撞）后转正常物理 |
| `camera.js` | 镜头 | `max(当前, 玩家位置 - 42% 视口)` 实现只进不退 |
| `game.js` | 游戏主控 | 状态机 play/dying/clear/gameover/win；渲染分层：背景→地形→道具→敌人→玩家→粒子→HUD |

## 技术选型说明

调研了 GitHub 上主流实现后选择 **原生 ES Modules + Canvas 2D**：

- **FullScreenMario**（jakecoffman/JoshuaKGoldberg）：最完整复刻，但基于自研 EightBittr/GameStartr 框架 + Grunt 构建，22 个模块对学习型项目过重
- **Mario.js**（jacobgeisler 系）：手写 Canvas 引擎，其"实体更新→碰撞→分层渲染"的主循环结构与瓦片索引碰撞方案被本项目借鉴
- **tylerreichle/mario_js**：Vanilla JS + Webpack，其死区跟随镜头与函数式 MapBuilder 建图思路被本项目借鉴
- **algorithm0r/SuperMarioBros**：大学课程项目，JSON 关卡 + 资产管理器，结构清晰但需加载外部素材
- **jonbarrow/SuperMarioBros**：P5.js 实现；**DomenicoPH/super-mario-clone**：Phaser + Vite

结论：对"可运行的初步框架"而言，零依赖原生方案启动成本最低、每行代码可控，物理与碰撞自实现也便于精确还原经典手感；后续若要做多关卡/编辑器/音效，可平滑迁移到 Phaser 或引入构建工具。
